## Semantics and guardrails

- iOS: Apple Native Acquisition contains first-time downloads and Apple's native CVR. Product Page Engagement is a separate table; it never forms a continuous funnel with native acquisition. Eligible native impressions appear only if actually available. Missing impressions remain absent, never reconstructed by dividing first downloads by rounded CVR. Page views are not an eligible denominator for first downloads. Native CVR uses total downloads + pre-orders over unique-device impressions; its absolute numerator/denominator are not available in current canonical rows.
- Android: matched listing visitors → listing acquisitions uses the CVR row's exact numerator, denominator and identical observed date sets. All observed listing visitors and device downloads stay separate, with their own partial coverage. EasySpell's 66 matched visitors are not confused with its 79 visitors over a wider window.
- Payment: eligible first-open cohort → paywall reached is distinct from all weekly paywall viewers → checkout → client ack. The weekly chain requires matching populations, calendar, observation cutoffs, exact numerator/denominator continuity and existing ordered-journey definitions. Client ack and RevenueCat initial paid transactions are not connected by an identity arrow.
- Usage: exact WAU = Any Core + No Core must reconcile, along with canonical reach numerators/denominators and population/source scope. Repeat / Any Core is a display ratio of already canonical counts; repeat means at least two distinct sessions with core value. No Core diagnostic counts must fully partition the same No Core population before percentages appear. Colored bars contain 32 rounded cells; adjacent exact counts and complementary one-decimal percentages sum to 100%.
- Features: retain canonical feature reach / WAU. Core penetration additionally requires evidence that feature users belong to the same active-core set, not merely a numerically smaller count. A private scope audit stores only booleans and a canonical week fingerprint, never new metric values or identities. Stale/missing proof suppresses %Core. The W37 read-only audit found late provider events after finalization; current source populations did not exactly match the frozen warehouse. W37 %Core therefore remains unavailable. No final values were rewritten. Feature use overlaps and must not sum to 100%; use ranked tables, never a pie chart.
- EasySpell Android: small sample, no Top/Bottom ranking. Observed activity counts are explicitly completion users; event occurrences are not inferred from distinct-user counts.
- EasySpell iOS: all five existing counters are queried over the same seven UTC ingestion days, for iOS / App Store-tagged / numeric release versions. W37 reread reconciled exactly: 54 app opens, 86 session starts, 85 learning starts, 48 completions and 323 activity completions, all tagged version 1.0.16. The compatible aggregate event ratio is 48/85 = 56.5%; it is not a same-session completion probability or unique-user rate. Production population remains partial because unlabelled channels and other versions are excluded. Dates with recorded matching events (two or three days) are distinct from seven-day query coverage. A hash-bound audit validates the five unchanged W37 canonical rows; future open-week rows preserve query boundaries and population metadata directly in canonical Notes. Changed/missing proof or differing learning populations suppress the ratio. No Mixpanel activation.

## Diagnostic economics and mature-cohort audit

Verified attributable media components remain visible even when total business CPI is unavailable. Known Media Cost Floor / Store Download = verified attributable media component / complete observed store downloads. It requires exact app/platform/week/calendar, known currency and a positive complete seven-day denominator. The numerator may be a verified subset within that same week: unknown other accounts/networks do not block a lower bound. Out-of-window numerator dates, partial denominators, unverified calendars or unlike cross-store counting units block it. It explicitly excludes unknown media and UGC and is never Business CPI. Network Paid CPI uses the mapped network-attributed install component and the same compatibility checks.
