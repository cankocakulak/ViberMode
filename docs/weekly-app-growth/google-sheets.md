## Refresh after each successful canonical readback

Use the connected Google Drive Sheets tools. No new Google credential or browser login is required.

1. Get live workbook metadata, and read the populated Ozard/EasySpell areas if necessary. Confirm the three owned sheet IDs and titles. To obtain native `merges` and `rowGroups`, use `batch_update_spreadsheet` with the idempotent property assignment `updateSheetProperties: {properties: {sheetId: 21092203, hidden: true}, fields: "hidden"}`, `include_spreadsheet_in_response: true`, `response_include_grid_data: false`. Save its `updatedSpreadsheet` object privately as `tmp/weekly-sheets-refresh/sheet-state.local.json`. An empty request list is rejected by the connector.
2. Run:

   `node scripts/weekly-google-sheets.mjs --sheet-state tmp/weekly-sheets-refresh/sheet-state.local.json`

   This reads the canonical warehouse using existing secure auth, validates every FINAL manifest, and prepares native Sheets request batches. It does not write Notion or invoke any provider collector. Current Istanbul week is appended for budget planning; every historical canonical week remains a column. Optional `--warehouse` is for a just-verified readback/test only, never an old collector cache.
3. Read `tmp/weekly-sheets-refresh/plan.local.json`. Submit each numbered `batch-NN.local.json` request list in order to the same workbook with `google_drive_batch_update_spreadsheet`. Only owned tabs are targeted. Batch 0 resets presentation merges/groups and clears only these generated tabs; subsequent batches restore the complete projection. Do not stop between preparation and publication unless a request fails. On an uncertain or interrupted run, fetch fresh native metadata and prepare again; do not replay stale row-group deletion requests. No tabs are deleted/recreated and no duplicate week columns are appended.
4. Read back both visible matrices using `get_spreadsheet_cells` with `userEnteredValue,effectiveValue,formattedValue`, and the hidden source using `userEnteredValue`. Compare nonempty inputs/formulas to the prepared requests (Google normalizes empty strings and leading zeros in DATE arguments); check all effective values for formula errors. Verify canonical source rows, current budget links, FINAL status and partial coverage labels. Record the receipt privately in `docs/weekly-app-growth/google-sheets-last-publish.local.json`. A failed readback is a failed Sheets publication, even if Notion succeeded.
5. Prefer visual verification via an authenticated browser when available. The connected account can have workbook access even when the browser account does not; do not request sharing changes. Use an XLSX export/render fallback or direct formatting readback.

Run focused checks with `node --test tests/weekly-google-sheets.test.mjs tests/sheets-economics.test.mjs` after changing this adapter. `buildWeeklySheets` is deterministic for the same canonical pages/lifecycle/current week and fresh sheet structure. Reruns reset groups before rebuilding, so group depth and week columns do not accumulate.

## Budget and CPI semantics

The Store acquisition presentation combines each native conversion's counts and rate in one weekly cell. Apple First Downloads / PPV remains a non-causal period proxy. Play conversion uses its canonical matched numerator/denominator, which can differ from the independently observed visitor total. Device Downloads stay separate. Coverage is visible beside the relevant flow; the eight numeric detail rows are collapsed under “Sayısal detaylar”. `sheets-store-summary.mjs` runs after the compact/hierarchy overlays and preserves all downstream row positions. Full refresh removes prior row groups before recreating them.

`Haftalık Giriş` columns are resolved by exact row-2 headers (Hafta seç →, App / proje, Bütçe hedefi $, Gerçek harcama $, Harcama geçerli), within fresh sheet metadata bounds. As of October 1 these are A/C/F/G/X; adding Hedef Ülkeler had shifted the old E/F/V references. Header-based INDEX/MATCH keeps the existing budget links valid after column moves. Missing headers produce a readback error rather than silently summing another column. The app tabs sum every matching channel/period, including split-month periods. The verified actual and budget delta only become numeric when every registered app/week row has Harcama geçerli=1. Blank actual cells stay unavailable.

Budget completeness is not full acquisition-cost coverage: it cannot prove absent networks, shared allocation or final UGC. Business CPI continues to come from the canonical metric. Known network amounts and the existing `knownMarketing` subtotal remain visibly separate. TRY/USD are never silently combined or converted. Existing compatibility helpers govern platform totals and WoW; provisional compatible comparisons retain the week-level provisional label.

The user's budget inputs can be edited normally. Generated app/source tabs are refreshed from canonical data and should not be used as manual metric-entry sheets.

## Compact spend, paid installs and country presentation

`sheets-economics.mjs` places known media spend and paid installs together for General, iOS and Android. Web remains a separate unallocated scope. Incomplete paid-install totals show `≥`; incomplete spending is explicitly known spending, never a complete total. UGC remains separate and is not arbitrarily split by platform. Business CPI continues to require the existing canonical complete-cost definition.

Network diagnostics use three short labeled lines in each weekly cell: Harcama, Paid install, CPI. Missing spend explicitly says Veri alınamadı and CPI says Harcama eksik; zero installs say 0 install · hesaplanmaz. There are no unlabeled arrows in economics cells. Platform summaries use two labeled lines, keeping week columns and existing row positions stable. In particular, EasySpell Google iOS spend must use Google installs, not the larger Google + Apple Ads total. Zero installs leave CPI unavailable. A short calendar caveat remains visible. Ozard Meta platform costs are derived only from the explicit audited splits in canonical Notes; every split must sum to the canonical source amount before the formula displays it. Web cost is not allocated to mobile platforms, and campaign geography names are not used to infer country spending.

Country rows show iOS / Android / total paid installs, with the latest available week's Top 5 followed by Rest. An absent country becomes zero only after country totals reconcile with the corresponding global paid-install scope. Incomplete scopes preserve the minimum marker. Additional countries, source networks and coverage details are collapsed. Country CPI is shown only when the country paid denominator can be tied to the same network: currently EasySpell Android's complete paid population is Google-only. Mixed-network iOS country installs cannot be divided into Google-only country spend. Known partial cost divided by a partial paid denominator is not presented as an overall CPI or a lower bound.

The summary and country cells remain formulas over `_Weekly Source`. No independent warehouse, provider collection, FINAL rewrite or budget-input change is introduced by this presentation update.

CPI/CVR readability pass: Store conversion now shows the native percentage first and its denominator/numerator immediately below, in division order. Apple native CVR is (Total Downloads + pre-orders) / unique-device impressions; preserve the provider-reported percentage and do not recompute it from a daily average. The current Play source is Statistics / Legacy store listing performance: matched listing acquisitions / eligible listing visitors on the same observed dates, not Device Downloads and not button-click CTR. PPV period proxy remains explicitly separate, with differing source calendars disclosed when unavailable. Store and economics values remain unchanged; this update changes labels/formula presentation and bounded row heights only.
